# feedme

A Claude Code plugin that makes noise when Claude is waiting for you.

Claude finishes a turn, you are on another window, and nothing happens for
ten minutes. With feedme, if you have not answered after a few seconds, your
computer plays a sound (by default Audrey II shouting *"Feed me!"*). It can
also call your webhooks or run your scripts, for example to blink a lamp
through Home Assistant.

- Sound sets you can switch with one command, and add your own by dropping files in a folder
- Webhooks with optional headers, and plain scripts, run when the alert fires
- On/off switch and a configurable delay
- Bash only, no runtime to install. macOS out of the box, Linux best-effort

## How it works

```text
Claude stops ──► Stop hook arms a timer for this session
                      │
                      ├─ you type, a tool runs, or the session ends ──► timer cancelled
                      │
                      └─ timeout passes with no answer ──► sound + your actions
```

Each Claude Code session has its own timer, so several terminals do not get in
each other's way.

## Install

Inside Claude Code:

```text
/plugin marketplace add thekoma/feedme
/plugin install feedme@feedme
```

Or from a shell:

```sh
claude plugin marketplace add thekoma/feedme
claude plugin install feedme@feedme
```

Start a new session, then try `/feedme:play` to hear the active set.

## Commands

| Command | What it does |
|---------|--------------|
| `/feedme:on` | Turn the alert on |
| `/feedme:off` | Turn the alert off |
| `/feedme:status` | Show on/off, timeout, sound set, audio player and actions |
| `/feedme:timeout [seconds]` | Show or set how long Claude waits before the alert (1 to 86400, default 10) |
| `/feedme:list` | List the sound sets; `*` marks the active one |
| `/feedme:set <name>` | Choose the sound set |
| `/feedme:play [name]` | Play a sound now, from the active set or the one named |
| `/feedme:hook add <name> '<url>' ['Header: value'...]` | Call a webhook when the alert fires |
| `/feedme:hook list` | List webhooks and scripts, with secrets masked |
| `/feedme:hook test [name]` | Run the actions now and show the result |
| `/feedme:hook rm <name>` | Remove a webhook |

The same commands work from a terminal with the script itself, for example
`~/.claude/plugins/marketplaces/feedme/scripts/feedme.sh status`.

## Configuration

Settings live in `~/.config/feedme/config` (or `$XDG_CONFIG_HOME/feedme/config`),
outside the plugin folder. They survive plugin updates and are shared by every
Claude Code profile on the machine, including ones started with
`CLAUDE_CONFIG_DIR`.

```ini
enabled=1
timeout=10
set=feedme
```

Use the commands above rather than editing the file by hand; if you do edit it,
an invalid value falls back to its default.

Environment variables, mostly for testing and special setups:

| Variable | Effect |
|----------|--------|
| `FEEDME_DELAY` | Overrides `timeout` for the sessions that see it |
| `FEEDME_PLAYER` | Path of the audio player to use instead of auto-detection |
| `FEEDME_CONFIG_DIR` | Use another config folder |
| `FEEDME_ACTION_TIMEOUT` | Seconds before a hanging script is killed (default 10) |
| `FEEDME_TRACE` | File where every `arm`, `cancel` and `fire` is logged, for debugging |

## Sound sets

| Set | Sounds | Source |
|-----|--------|--------|
| `feedme` (default) | Audrey II asking to be fed | *Little Shop of Horrors* (1986) |
| `8bit` | pipe dive, game over, power-up, jump | Original chiptune, generated by `tools/make-8bit.py` |
| `sitcom` | laughs, applause, "ooh", "aww", sigh | CC0 clips from Freesound |
| `cartoon` | boing, spring, slide whistle, bonk, pop | CC0 clips from Freesound |

When the alert fires, feedme picks one sound at random from the active set.
Every set has a `CREDITS.md` with the source and license of each file.

### Use your own sounds

A set is just a folder of audio files. Create one in `~/.config/feedme/sounds/`:

```sh
mkdir -p ~/.config/feedme/sounds/mine
cp ~/Downloads/*.wav ~/.config/feedme/sounds/mine/
```

Then run `/feedme:list` to see it and `/feedme:set mine` to use it.

To **replace** a bundled set, create a folder with the same name: a set in
`~/.config/feedme/sounds/feedme/` is used instead of the bundled `feedme`.
Remove the folder to get the original back.

Set names may contain letters, digits, `.`, `_` and `-`. Files the audio player
cannot decode are ignored:

| Player | Platform | Formats |
|--------|----------|---------|
| `afplay` | macOS | wav, aif, aiff, mp3, m4a, caf |
| `paplay`, `pw-play` | Linux | wav, aif, aiff, flac, ogg |
| `aplay` | Linux | wav |
| `ffplay`, `mpv` | any | all of the above |

WAV works everywhere. To convert and trim a clip, and match the loudness of the
bundled sounds, use the import tool that ships with the plugin (it needs
`ffmpeg`):

```sh
~/.claude/plugins/marketplaces/feedme/tools/import-sound.sh \
  input.mp3 ~/.config/feedme/sounds/mine/clip.wav [start-seconds] [duration-seconds]
```

### Share a set

Pull requests with new sets are welcome. Add a folder under `sounds/` with the
WAV files and a `CREDITS.md` listing source, author and license for each one.
Only include sounds you are allowed to redistribute (CC0, public domain, or
your own recordings).

## Actions: webhooks and scripts

Actions run at the same moment as the sound. They live in
`~/.config/feedme/hooks.d/`, and you can have as many as you like.

### Webhooks

```text
/feedme:hook add lamp 'https://homeassistant.local:8123/api/webhook/<your-webhook-id>'
/feedme:hook add notify 'https://example.com/hooks/claude' 'Authorization: Bearer <token>' 'X-Source: feedme'
/feedme:hook test
```

feedme sends a `POST` with this JSON body:

```json
{"event": "feedme", "set": "feedme", "session_id": "…", "cwd": "/path/of/the/project"}
```

Things to know:

- **Single-quote the URL and every header.** The arguments go through a shell,
  so an unquoted `&`, `;` or `#` cuts the URL, and `$` gets expanded. After
  `add`, feedme prints the URL length so you can spot a cut-off URL.
- **What you type stays in the conversation history.** If a URL or header holds
  a secret you would rather keep out of the transcript, write the file yourself:

  ```sh
  mkdir -p ~/.config/feedme/hooks.d && chmod 700 ~/.config/feedme/hooks.d
  cat > ~/.config/feedme/hooks.d/lamp.webhook <<'EOF'
  url=https://homeassistant.local:8123/api/webhook/<your-webhook-id>
  header=Authorization: Bearer <token>
  EOF
  chmod 600 ~/.config/feedme/hooks.d/lamp.webhook
  ```

- Webhook files are created readable only by you, `/feedme:hook list` masks the
  URL path and header values, and curl receives URL and headers on stdin so
  they never show up in `ps`.
- Each request times out after 5 seconds.

### Scripts

Any executable file in `~/.config/feedme/hooks.d/` runs when the alert fires,
with these variables:

| Variable | Value |
|----------|-------|
| `FEEDME_SET` | Active sound set |
| `FEEDME_SOUND` | Path of the sound being played |
| `FEEDME_SESSION_ID` | Claude Code session id |
| `FEEDME_CWD` | Working directory of the session |

For example, a desktop notification on macOS:

```sh
cat > ~/.config/feedme/hooks.d/notify <<'EOF'
#!/bin/bash
osascript -e "display notification \"Waiting in ${FEEDME_CWD##*/}\" with title \"Claude\""
EOF
chmod +x ~/.config/feedme/hooks.d/notify
```

On Linux, use `notify-send "Claude" "Waiting in ${FEEDME_CWD##*/}"` instead.
A script that runs longer than 10 seconds is stopped, together with every
process it started. Files that are not executable are ignored, so you can keep
notes in the same folder.

## Alerting on more Claude Code events

The plugin arms the alert when Claude stops (`Stop`) and cancels it when you
send a prompt, a tool starts, or the session ends. You can attach the same
script to other events from your own `settings.json`. The script is in the
marketplace copy of this repo, at
`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/marketplaces/feedme/scripts/feedme.sh`.

For example, to also be called when Claude is waiting for a permission
answer:

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "permission_prompt",
        "hooks": [
          { "type": "command", "command": "\"${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/marketplaces/feedme/scripts/feedme.sh\" arm", "timeout": 5 }
        ]
      }
    ],
    "PostToolUse": [
      {
        "hooks": [
          { "type": "command", "command": "\"${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/marketplaces/feedme/scripts/feedme.sh\" cancel", "timeout": 5 }
        ]
      }
    ],
    "PostToolUseFailure": [
      {
        "hooks": [
          { "type": "command", "command": "\"${CLAUDE_CONFIG_DIR:-$HOME/.claude}/plugins/marketplaces/feedme/scripts/feedme.sh\" cancel", "timeout": 5 }
        ]
      }
    ]
  }
}
```

Claude Code sends `permission_prompt` once a permission dialog has been open
for a few seconds. The `PostToolUse` and `PostToolUseFailure` entries matter:
the plugin cancels the alert before a tool starts, which happens before the
permission dialog, and nothing else cancels it once you approve. Without them,
a long command you approve could let the alert fire while Claude is still
working. Keep these hooks in shell form (a `command` string, no `args`) so the
`${CLAUDE_CONFIG_DIR:-$HOME/.claude}` part gets expanded.

`arm` and `cancel` read the hook JSON from stdin, always exit 0 and never print
anything, so they are safe on any event.

To change the default events for everyone, fork the repo, edit
`hooks/hooks.json`, and install your fork instead.

## Troubleshooting

- **No sound:** run `/feedme:status`. It shows whether feedme is on, the
  timeout, the active set and the audio player found. `/feedme:play` plays a
  sound immediately.
- **The sound plays twice:** you probably still have hand-written feedme hooks
  in `settings.json` from before the plugin. Remove them.
- **Nothing happens at all:** start Claude with `FEEDME_TRACE=/tmp/feedme.trace`
  and check that the file gets `arm` and `cancel` lines. If it stays empty, the
  plugin is not enabled: check `/plugin`.
- **Silence it for a while:** `/feedme:off`, then `/feedme:on`.

## Platforms

- **macOS:** tested; uses `afplay`, which ships with the system.
- **Linux:** best-effort; needs one of `paplay`, `pw-play`, `aplay`, `ffplay`
  or `mpv`, and `curl` for webhooks.
- **Windows:** not supported (WSL may work with a Linux player).

`jq` is used when present to read the hook input; without it a simpler parser
takes over.

## Uninstall

```sh
claude plugin uninstall feedme@feedme
claude plugin marketplace remove feedme
rm -rf ~/.config/feedme   # settings, your sound sets and actions
```

## Development

```sh
/bin/bash tests/run.sh                     # test suite, under the oldest bash we support (3.2)
shellcheck -x scripts/feedme.sh scripts/lib/*.sh tests/run.sh tools/*.sh
claude plugin validate .
claude --plugin-dir .                      # try your working copy
```

Layout:

| Path | Purpose |
|------|---------|
| `scripts/feedme.sh` | Entry point for hooks and commands |
| `scripts/lib/config.sh` | Settings file |
| `scripts/lib/sounds.sh` | Sound sets and audio players |
| `scripts/lib/alert.sh` | arm, cancel and fire |
| `scripts/lib/actions.sh` | Webhooks and scripts |
| `hooks/hooks.json` | Claude Code events the plugin listens to |
| `skills/*/SKILL.md` | The `/feedme:*` commands |
| `sounds/<set>/` | Bundled sound sets |
| `tools/` | Sound generation and import |
